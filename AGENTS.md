# AntiMirror — инструкции агенту

## Начни здесь

Это реализация desktop-расширения WXT + TypeScript + vanilla HTML/CSS, Manifest V3.
Прочитай `docs/antimirror/00_PRODUCT.md`, `01_TECHNICAL_SPEC.md`, `09_PROGRESS.md`,
`11_HANDOFF.md`, затем текущий слайс из `docs/antimirror/slices/README.md`.
Не загружай всю историю проекта без необходимости.

При наличии старого кода сначала сопоставь его с новым контрактом. Не удаляй пользовательские
изменения, существующий LICENSE, AGENTS или навыки вслепую. Текущие требования ручного запуска
и сброса важнее старого allowlist, автозапуска, глобального enabled или устаревшего ТЗ.

## Инварианты

- Включение только по доверенному действию пользователя. Popup-open, FRAME_READY,
  мутации DOM и сообщения страницы никогда не включают отражение.
- Один выбранный video на одну явно активированную вкладку. Не отражать родителей,
  iframe, всю страницу, все найденные ролики или новый video после потери старого.
- Контроллер background — единственный писатель состояния. Иконка ON только после ACK
  выбранного документа и подтверждения текущей операции.
- `tabId + documentNonce + operationId + targetId` защищают от запоздавших сообщений.
  `frameId` без идентификатора документа недостаточен.
- OFF = нет прикладного DOM-сканирования, DOM-observers, timers и зеркального эффекта.
  Пассивный runtime-listener допустим. У фоновых браузерных событий есть собственная стоимость.
- Не затирать `style`, `transform`, чужие анимации или `adoptedStyleSheets`.
- Обычный сон MV3-worker не сбрасывает режим и не рассинхронизирует иконку с видео.
  Использовать native `storage.session`, не `storage.local` для enabled.
- Не читать кадры, звук, историю просмотра и cookies; нет аналитики и внешнего backend.
- Не обходить DRM, CSP, sandbox и запрет инъекции на защищённых страницах.
- `defineBackground()` и `defineContentScript()` обязательны. Runtime DOM-код только
  внутри `main(ctx)`. Все фоновые listeners регистрировать до первого `await`.
- Firefox строить явно как MV3 и проверять итоговый manifest. Не считать сборку доказательством
  работоспособности закрытых roots, PiP или реальных видеоплатформ.

## Работа

Используй навык `antimirror-implement-slice` или явно прочитай
`.agents/skills/antimirror-implement-slice/SKILL.md`.
Делай один законченный слайс за запуск, если пользователь не задал другой объём.
Не заменяй реализацию бесконечным планированием. Разумные локальные решения фиксируй и выполняй.
Не переходи через обязательный блокирующий gate, выдавая его за пройденный.

После работы: тесты, review diff, обновление progress, handoff, техдолга и затронутых
канонических документов. Пиши точные команды, результаты и то, что не удалось проверить.
Не помечай ручные браузерные проверки `PASS`, если их не выполнял.

Не меняй глобальные настройки Codex, системные skills и чужие процессы. Не публикуй расширение,
не пушь в remote и не выполняй разрушительные команды без отдельного поручения.
Локальные порты тестового стенда настраиваемые; при конфликте выбери свободные, не убивай процесс.

## Команды после S00

Node 24.13.0 (`.node-version`), pnpm 10.29.2. Установка: `pnpm install --frozen-lockfile`.
Проверки: `pnpm typecheck`, `pnpm lint`, `pnpm test:unit`, обе `pnpm build:chrome` /
`pnpm build:firefox`, затем `pnpm verify:manifests`.
`pnpm test:e2e:chromium` проверяет production popup, `pnpm test:e2e:feasibility` — S00;
обе команды запускают собственный стенд. `pnpm test:e2e:firefox` и
`pnpm test:worker-idle` требуют запущенного `pnpm fixtures`. Порты согласовать через env.
`.output-spike` — только feasibility, не распространять её как обычное расширение.
Не подключать worker debugger при проверке естественного MV3 idle.
