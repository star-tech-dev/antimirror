# Работа агента по слайсам

## Вход

AGENTS.md → progress/handoff → текущий slice → только относящиеся к нему разделы ТЗ.
Существующие код/инструкции — источник фактического состояния, но не основание вернуть
устаревшие функции. При конфликте новый пользовательский контракт имеет приоритет.

## Цикл

1. Inspect: git status, текущая реализация, незакоммиченные изменения, имеющиеся тесты.
2. Scope: несколько конкретных шагов текущего слайса, критерии DONE, зависимости.
3. Implement: минимальный законченный результат, без speculative frameworks/пустых слоёв.
4. Verify: целевые тесты, regression, lint/types/build; inspect generated manifest при изменении WXT.
5. Review: diff на нарушения инвариантов, ownership, browser assumptions и доверенные границы.
6. Handoff: актуализировать progress/долг/решения/следующий шаг; отчитаться фактами.

Обновляй инструкции и skill только если изменились фактические workflow, команды или
инварианты. Не переписывай AGENTS ради формального «освежения» в каждом запуске.

## Definition of Done любого слайса

Реализованы критерии слайса; нет заведомого нарушения уже обязательных инвариантов;
новые ветки ошибок/cleanup покрыты; выбранные команды фактически выполнены;
ручные проверки отмечены отдельно; документация не противоречит коду.

Отсутствующий инструмент — явно NOT_RUN/BLOCKED. Успешный unit mock не заменяет browser gate.
Частичный результат полезен, но не называется завершённым слайсом. Не повторять тот же
безуспешный подход многократно без изменения гипотезы.

## Результат запуска

Используй короткий отчёт:

```text
Слайс:
Что изменено:
Проверки: команда -> результат
Browser evidence:
Не проверено / блокеры:
Принятые решения:
Техдолг:
Следующий точный шаг:
```

Создавай `docs/antimirror/evidence/Sxx-YYYY-MM-DD.md` для содержательных результатов;
не копируй полные логи в каждый документ. Артефакты тестов и чувствительные данные не коммитить.

## Параллелизм

По умолчанию один implementation writer в рабочем дереве. Review можно выполнять независимо,
но без одновременной записи тех же файлов. Отдельные задачи допускаются в worktrees с ясными
границами. Не строить multi-agent orchestration для небольшого расширения.

Порты fixture-lab задаются окружением. При занятом порте выбрать другой; не останавливать
чужие проекты или незнакомые процессы пользователя.
