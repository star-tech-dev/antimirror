## Popup language

The header has an accessible EN/RU selector. The choice is stored as the standalone
`popupLocale` preference in `storage.local`; changing it only reloads local message catalogs and
rerenders the last background-owned state. It never sends `SET_ENABLED` or starts discovery.

Chromium production E2E verified EN → RU, persistence after closing/reopening the popup and RU →
EN while state stayed OFF. Firefox native UX regression passed with the new add-on ID. Manual
Firefox toolbar UI remains `NOT_RUN` under the previously accepted skip.

## Brand and store preparation

- Image generation supplied the initial logo direction; committed SVG geometry makes all runtime
  sizes deterministic and legible at 16 px.
- Separate brand, OFF and ON icon families were rendered at 16/32/48/128 and visually inspected.
- Toolbar screenshot review found that store-style padding reduced the state glyph to about 12 px
  inside the 16 px canvas. OFF/ON artwork now occupies 124/128 of the canvas (about 15.5 px at
  toolbar size); the store brand icon keeps its required transparent padding.
- Reproducible assets: 440×280 promo, 1400×560 marquee and localized EN/RU 1280×800 screenshots.
- Natural-language EN/RU summaries and descriptions, single-purpose statement, permissions
  justifications and privacy dashboard answers are in `store-assets/listing/`.
- A static privacy page is ready in `store-assets/privacy.html`. It still requires hosting before
  submission.

Chrome's official guidance says local website-content/browsing-activity processing must be
disclosed even without external transmission. Firefox's `data_collection_permissions: none`
remains accurate because Mozilla defines that field around collection and transmission outside
the extension. Sources checked:
