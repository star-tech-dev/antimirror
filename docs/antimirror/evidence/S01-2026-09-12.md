# S01 · Первый полный ручной сценарий · 2026-09-12

Статус: **DONE**. База: `d64a05c` (S00). Среда: macOS 26.5 arm64,
Chrome for Testing 153.0.8010.12, Node 24.13.0, pnpm 10.29.2.

## Что реализовано

Production popup отправляет versioned `GET_STATE` / `SET_ENABLED(desired, requestId)`.
Background проверяет точный popup URL и активный tabId, затем проводит один top-frame video
через PROBE, DISCOVER, PREPARE_APPLY, APPLIED, COMMIT и COMMITTED. Только после COMMITTED
state становится ON и action получает ON icon/title. OFF сначала инвалидирует operation,
затем снимает только принадлежащий ей Animation.

State — discriminated union с revision, operationId и topDocumentNonce; TargetRef содержит
frameId=0, documentNonce, opaque targetId и mediaToken. Native storage.session — источник
восстановления, background controller — единственный writer. Runtime guards ограничивают IDs
и candidates. Request cache ограничен 64 элементами и не использует keepalive timers.

Content agent идемпотентен при повторной инъекции. В OFF остаётся только passive listener;
нет observers, polling или DOM refs candidates. Discovery — один синхронный top-document pass
только после user intent, максимум два кандидата. Это сознательная граница S01.

## Найденные и исправленные проблемы

Первый rapid-click E2E показал гонку: OFF мог завершиться до ответа PROBE, после чего поздний
ON продолжал работу. `pendingOperations` теперь создаётся до PROBE и удаляется OFF; late response
получает CANCEL_OPERATION. Operation не записывается как активная до получения documentNonce.

Cleanup сначала использовал action/storage commit до DISABLE: сбой presenter мог оставить
effect. Теперь captured previous target очищается независимо от ошибки записи/иконки, затем
public handler возвращает безопасный APPLY_FAILED. Unit tests воспроизводят обе ветки.

Playwright не выдал action popup через обычный `page` event, хотя Chrome создал page target.
Harness использует scoped CDP attach к этому target. Production код не менялся ради теста.
