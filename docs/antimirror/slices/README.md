# План разработки

Слайсы — законченные проверяемые increments, а не отдельный запуск на каждый файл.
План не является оценкой часов и не требует конкретной марки модели. Effort ниже —
рекомендация глубины рассуждения, не утверждение о доступности параметра в аккаунте.

|---|---|---|---|

| [S01](./S01_VERTICAL_SLICE.md) | Первый полный ручной сценарий | S00 | High |

## Базовые восемь и post-RC polish

Сначала подтверждаются механизмы браузера, затем появляется первый работающий вертикальный
сценарий. После этого отдельно добавляются deep DOM и frame coordination, затем lifecycle
и MV3 recovery. UX, hardening и release не смешиваются с новым функционалом.

S08 добавлен после завершения исходных восьми слайсов по прямому запросу владельца. Он не меняет
runtime-контракт зеркалирования: только версия/identity, локальная UI-настройка и release assets.

Так не приходится реализовывать сложный scanner до первого работающего включения, но и
не откладываются критические browser assumptions до конца проекта.

Не дробить автоматически каждый раздел на ещё десять «слайсов». При большом diff внутри
слайса допустим промежуточный handoff со статусом IN_PROGRESS. При уже готовом коде агент
может доказать соответствие существующего модуля, а не переписывать его ради галочки.
