# 10. Технический долг

На момент подготовки пакета код расширения не изучен: **подтверждённый техдолг не записан**.
Не создавать фиктивные completed/overdue задачи. Потенциальные риски — в 12_RISKS_AND_VALIDATION.md,
будущие продуктовые функции — в 00_PRODUCT.md, а не в этом реестре.

| ID | Severity | Конкретная проблема | Evidence | Почему отложено | Исправление / слайс | Статус |
|---|---|---|---|---|---|---|

Каждый долг должен иметь воспроизведение или конкретный code smell с последствиями и
проверяемый критерий закрытия. Блокирующие нарушения ручной активации, потери state,
ложного ON, утечек и unsafe transform нельзя просто перенести на «после релиза».
